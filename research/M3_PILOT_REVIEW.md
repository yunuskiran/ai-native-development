## Editorial checks and retained issues

- **Narrative:** C01 owns responsibility/history framing, C04 follows a native artifact trail, C10 owns conditional decisions. The companion supplies a short case story without replacing chapter 11.
- **Scope:** C01 has only two verified historical anchors. Its title promises more history than this pilot supplies. Broader chronology requires new primary sources before full-length expansion.
- **Practicality:** C04 now contains a routing note, a specification-content sketch and proposed acceptance boundaries. None is mislabeled as native generated output. A real artifact extract and command walkthrough require future execution evidence.
- **Depth:** C04 is a seven-section pilot, below the 5,500-word allocation; no claim of a complete, accepted method chapter is made. Team customization, broader module treatment and actual host behavior need further evidence if added.
- **Repetition:** Tenant/self-approval examples recur for different duties: accountability in C01, workflow in C04, selection constraints in C10, and business sequence in the companion. A later continuous-manuscript edit should shorten repeated setup once C03/C11 exist.
- **Balance:** No universal winner, intuitive score, adoption guarantee, performance multiplier or fabricated run appears. Case obligations cannot count as passing tests.
- **Originality:** Prose, tables and teaching examples were composed for this project. No outside prompts, figures, code or book passages were copied. Full-text Apress comparison and final originality/permissions clearance remain unavailable/pending; independently composed prose does not close that gate.
- **Reader friction:** Review banners belong to this pilot. Production will consolidate process metadata into version/source notes after acceptance; it must retain the meaningful evidence limits.
